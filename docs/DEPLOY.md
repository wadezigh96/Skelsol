## Fee math and rounding

`fee = price / 100` (integer division); the seller receives
`price - fee`. The fee rounds DOWN, so any rounding remainder goes to the
seller: a 1,000,001-lamport sale pays a 10,000-lamport fee and the seller
receives 990,001. For prices under 100 lamports the fee is 0.

`buy` takes no price argument: the program always charges the price stored
in the listing account, never client input. The fee recipient is the fixed
`TREASURY` constant in the program, never a client-supplied account.

## Treasury (placeholder)

`TREASURY` is currently the devnet deployer's wallet,
`7T1fjFsHvo3Q7EpwN5RzgNk8HARdxKnC3tgkavAbBQX7`, marked TODO in
`programs/skelsol-market/src/constants.rs`. The owner MUST replace it with
the real treasury address before any mainnet deploy (and redeploy).

Setup requirement: the treasury address must already hold SOL (an existing,
rent-exempt account) before the first sale. A fee payment to a brand-new
address fails, because a new system account must receive at least the
rent-exempt minimum (890,880 lamports) and a 1% fee is usually less than
that. A normal funded wallet satisfies this.

## Deploy

From the repo root, after funding:

```sh
./programs/skelsol-market/scripts/deploy-devnet.sh
```

The script checks the CLI config is devnet, checks the program keypair
matches the declared program ID, checks the wallet balance, builds, deploys
with `solana program deploy --program-id`, and prints `solana program show`
output plus the explorer link. After a devnet reset, re-run it to redeploy
(the program ID is stable because the keypair is stable).

Manual equivalent:

```sh
solana config set --url https://api.devnet.solana.com --keypair ~/.config/solana/id.json
anchor build
solana program deploy --url https://api.devnet.solana.com \
  --keypair ~/.config/solana/id.json \
  --program-id ~/.config/solana/skelsol-market.json \
  target/deploy/skelsol_market.so
solana program show --url https://api.devnet.solana.com 3XMFqwbEND9gYWoTahNQPhVoNspHet1PfdizsRymqwNo
```

If `solana program deploy` panics with a TPU client error
(`Should return a valid tpu client: PubsubError ...`), the devnet
pubsub endpoint is unreachable from the deploy machine. Re-run the
deploy with `--use-rpc` (sends the deployment through the RPC instead
of the TPU client):

```sh
solana program deploy --url https://api.devnet.solana.com \
  --keypair ~/.config/solana/id.json \
  --program-id ~/.config/solana/skelsol-market.json \
  --use-rpc \
  target/deploy/skelsol_market.so
```

A failed attempt may leave a funded buffer account behind (~1.05 SOL
each). List them with `solana program show --buffers --url
https://api.devnet.solana.com` and reclaim the rent with `solana program
close --buffers --url https://api.devnet.solana.com --keypair
~/.config/solana/id.json` (this closes buffers only, never the deployed
program).

## Devnet reset

Devnet "may be subject to ledger resets" (Solana clusters doc). A reset
wipes everything on devnet: the deployed program, all listings and
vaults, all minted inscriptions and carrier NFTs, and all devnet SOL
balances — including the deploy wallet's. Nothing survives a reset
except what lives in this repo (the program source, the binary, the
keypairs in `~/.config/solana/`, and these docs). Recovery is:

1. **Check what is gone.** `solana program show --url
   https://api.devnet.solana.com 3XMFqwbEND9gYWoTahNQPhVoNspHet1PfdizsRymqwNo`
   fails (account not found) after a reset, and the explorer link
   404s again.
2. **Re-fund the deploy wallet.** After a reset the wallet
   `7T1fjFsHvo3Q7EpwN5RzgNk8HARdxKnC3tgkavAbBQX7` holds 0 SOL again.
   Request fresh devnet SOL from the web faucet
   (https://faucet.solana.com) — ~3 SOL, same as the first deploy.
3. **Redeploy.** Re-run the same script from the repo root; the
   program ID is unchanged because the program keypair is stable:
   `./programs/skelsol-market/scripts/deploy-devnet.sh`
   Then verify with `solana program show` and the explorer link (see
   "Verify a deploy" above), and re-check the binary hash:
   `sha256sum target/deploy/skelsol_market.so` must still be
   `fd9022b981c7560c93944bfcb9d6c8f680d4f0513ee1f3fc361b89e4190adac3`
   unless the program source changed since.
4. **Re-seed demo state.** The reader rebuilds all collection state
   from the chain, so there is no database to reset — but the demo
   data itself is gone. Re-create it with the CLI (fund a demo
   keypair from the web faucet first):
   ```sh
   node cli/dist/cli.js mint --keypair ./agent-keypair.json
   node cli/dist/cli.js list <mint> 1000000000 --keypair ./agent-keypair.json
   ```
   Mint a few inscriptions and list one or two, so the apps show a
   live leaderboard, activity, and a floor price again. The treasury
   is the deploy wallet itself, so it is funded again by step 2 and
   satisfies the "treasury must already hold SOL" requirement.

If the reset happens close to demo day, do steps 1–4 in one pass and
re-run the judge path in `docs/SUBMISSION.md` to confirm everything
works end to end.

## Tests

`@coral-xyz/anchor` 1.x TS client on npm, latest is 0.32.1, so there are no

## Toolchain notes (gotchas found during this build)

- PATH for every command:
  `~/.cargo/bin:~/.local/share/solana/install/active_release/bin:~/.avm/bin`.
  Set `TMPDIR=$HOME/.cargo-tmp` for cargo commands (`/tmp` is 512 MB).
- anchor-cli 1.2.2, solana-cli 4.1.2 (the ticket says 4.3.2; the installed
  binary reports 4.1.2), rustc 1.100.0 (stable). Platform-tools v1.57
  (`cargo build-sbf --tools-version v1.57 --install-only` succeeds from the
  local cache; no download needed).
- `rust-toolchain.toml` pins `stable`, NOT the scaffold's 1.89.0: on 1.89
  the IDL build fails because solana-syscalls 4.2.2 uses
  `MaybeUninit::write_copy_of_slice` (stabilized in Rust 1.93, E0658).
- `Cargo.lock` is based on the lockfile shipped with the `anchor init`
  1.2.2 template (solana 4.1.x-era graph). Do not `cargo update` blindly:
  litesvm 0.15.2 does not compile against solana-program-runtime 4.2+
  (`ExecutionRecord` changed), and litesvm 0.18.x pulls a wincode 0.5/0.6
  split that breaks solana-loader-v3-interface 8.0.1.
- `idl-build` must be forwarded to anchor-spl
  (`idl-build = ["anchor-lang/idl-build", "anchor-spl/idl-build"]`), or
  the IDL build fails on the SPL account types.
- `init-if-needed` must be enabled on anchor-lang for the
  `init_if_needed` token accounts in `buy`/`cancel`. It is safe here (see
  the comment in `programs/skelsol-market/Cargo.toml`).
- `anchor build` runs the test binaries as part of IDL generation, so a
  broken test dependency breaks the build too.
